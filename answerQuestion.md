# Контрольні питання: Алгоритми сортування
-----
## 1\. Переваги та недоліки методів сортування

### Сортування бульбашкою (Bubble Sort)
- **Переваги:** Простий у розумінні та реалізації; стабільний; з адаптацією (прапорець перестановок) виконується за $O(n)$ для вже відсортованого масиву.
- **Недоліки:** Дуже низька ефективність $O(n^2)$; робить велику кількість операцій запису/перестановок у пам'яті.

### Сортування вибором (Selection Sort)
- **Переваги:** Виконує мінімальну кількість обмінів / записів у пам'ять — рівно $O(n)$; простий у реалізації.
- **Недоліки:** Часова складність **завжди** $O(n^2)$ (навіть для повністю відсортованого масиву); за замовчуванням є нестабільним.

### Сортування вставкою (Insertion Sort)
- **Переваги:** Найефективніший серед простих алгоритмів; стабільний; дуже швидкий на малих масивах ($n < 15$) та частково відсортованих даних ($O(n)$); працює в онлайн-режимі (може сортувати дані по мірі їх надходження).
- **Недоліки:** Квадратична складність $O(n^2)$ у найгіршому та середньому випадках.

-----
## 2\. Оцінка алгоритмів за критеріями

| Алгоритм | Час (Найкращий) | Час (Середній) | Час (Найгірший) | Додаткова пам'ять | Стабільність |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Bubble sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |
| **Selection sort** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нестабільний |
| **Insertion sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Стабільний |

### Додаткові критерії порівняння:
- **Кількість операцій запису (Swaps):** Selection sort робить щонайбільше $n - 1$ перестановок, що критично для флеш-пам'яті чи повільних накопичувачів.
- **Адаптивність (Adaptability):** Insertion sort і Bubble sort є адаптивними (їхня швидкість зростає на частково відсортованих даних), тоді як Selection sort нереагує на початковий порядок.
- **Онлайн-сортування (Online nature):** Insertion sort може сортувати список безпосередньо під час отримання нових елементів.

-----
## 3\. Найкращі та найгірші випадки для алгоритмів

### Відсортований масив (Найкращий випадок)
- **Insertion Sort** та **Bubble Sort (з прапорцем):** Дають найкращий результат — $O(n)$, оскільки роблять лише один прохід без перестановок.
- **Selection Sort:** Дає найгірший можливий для себе результат — $O(n^2)$, бо все одно порівнює кожен елемент з усіма іншими.

### Масив, відсортований у зворотному порядку (Найгірший випадок)
- **Всі три алгоритми** працюють за $O(n^2)$.
- **Insertion Sort** та **Bubble Sort** роблять максимальну кількість зсувів/перестановок ($\approx n^2/2$).
- **Selection Sort** робить стільки ж порівнянь, але всього $n/2$ перестановок.

### Частково відсортований масив
- **Insertion Sort** забезпечує найкращий результат серед усіх трьох, показуючи складність, близьку до $O(n)$.

-----
## 4\. Значення O-нотації (Big O)

Позначення **Big O** показує асимптотичну верхню межу складності алгоритму при зростанні розміру вхідних даних ($n$):

- **$O(1)$ — Константна складність:** Час виконання або обсяг пам'яті не залежать від розміру масиву $n$ (наприклад, доступ до елемента за індексом `array[i]` або створення однієї змінної).
- **$O(n)$ — Лінійна складність:** Час виконання зростає прямо пропорційно кількості елементів $n$ (наприклад, один прохід по масиву циклом для пошуку суми).
- **$O(n^2)$ — Квадратична складність:** Час виконання зростає пропорційно квадрату кількості елементів (наприклад, вкладені цикли при сортуванні $n \times n$). Якщо розмір масиву збільшиться в 10 разів, час роботи зросте приблизно в 100 разів.
